# StorageLens Custom Prompt

You are working on **StorageLens**, a microservices-based storage analytics and duplicate detection platform built with .NET 8. The system is designed with strict service boundaries and polyglot persistence.

## Architecture Context

**Services & Data Ownership**:
- `StorageLens.Web` (5001) → UI layer in Razor Pages + Bootstrap 5
- `Locations` (5101) → Location metadata DB context
- `ScanJobs` (5102) → Scan job state and progress
- `FileInventory` (5103) → File metadata and hashes
- `Duplicates` (5104) → Duplicate group calculations
- `Analytics` (5105) → Dashboard aggregations
- `Scanner` (5106) → File system traversal
- `Hashing` (5107) → SHA-256 computation
- `Orchestrator` (5108) → Workflow coordination

**Communication**: HTTP APIs only; cross-service database access is forbidden.

## Before Every Change

Ask yourself:
1. **Which service owns this?** Does the change belong in the right project?
2. **Is this a contract change?** Does `StorageLens.Shared.Contracts` need updating?
3. **Do I need HTTP calls?** Is the service boundary crossed? Register typed `HttpClient`.
4. **Will tests pass?** Service logic requires unit tests.
5. **Is documentation affected?** Any API, workflow, or deployment change must update `docs/` and `docs/CHANGELOG.md`.

## Coding Conventions

- **C# style**: Idiomatic, meaningful names, immutable DTOs
- **Logging**: Always include correlation IDs for cross-service tracing
- **Error handling**: Explicit status codes; distinguish recoverable vs. terminal failures
- **API design**: REST endpoints with JSON; backward-compatible contracts
- **Testing**: Unit tests for all business logic; mock HTTP clients

## Documentation Guard

**MANDATORY**: If you modify source code, config, workflows, or tests, at least one file in `docs/` must change, AND `docs/CHANGELOG.md` must be updated. This is enforced by CI.

## Common Patterns

**Adding a service endpoint**:
```csharp
// 1. Define DTO in StorageLens.Shared.Contracts
public record CreateLocationRequest(string Name, string Path);

// 2. Create controller in the service
[ApiController]
[Route("api/locations")]
public class LocationsController : ControllerBase { ... }

// 3. Register typed client in consumer
services.AddHttpClient<ILocationService>(client => {...});

// 4. Write tests
// 5. Update docs/technical/api-specification.md
// 6. Update docs/CHANGELOG.md
```

**Cross-service call with retry**:
- Use typed `HttpClient` registered in DI
- Propagate correlation IDs in headers
- Handle `HttpRequestException` explicitly
- Log failures with correlation context

## Red Flags

🚫 Direct cross-service database queries  
🚫 Hardcoded credentials (use managed identities or KeyVault)  
🚫 API changes without updating `Shared.Contracts`  
🚫 Missing unit tests  
🚫 Code changes without documentation updates  
🚫 Silent error handling (must log actionable context)
