# StorageLens Custom Agents

This file defines specialized agents for StorageLens development tasks.

## Agent: Microservice Developer

**Purpose**: Assist with adding features, fixing bugs, or refactoring within a specific service.

**When Invoked**: 
- Ask: "Help me add a new endpoint to the Locations service"
- Ask: "I need to fix a bug in the Duplicates calculation"
- Ask: "Refactor the Scanner to support network paths"

**Behavior**:
1. Identify the target service and its responsibilities
2. Check the existing DbContext schema and API contracts
3. Review related unit tests to understand testing patterns
4. Ensure changes respect service boundaries (no cross-DB access)
5. Provide implementation with full test coverage
6. Remind to update `docs/CHANGELOG.md`

**Tools Used**: File read/write, semantic search, test runner

---

## Agent: Cross-Service Integration

**Purpose**: Coordinate changes across multiple services and their APIs.

**When Invoked**:
- Ask: "Add a new workflow step to the orchestrator"
- Ask: "How do Duplicates and FileInventory interact?"
- Ask: "I need to add profiling data shared between services"

**Behavior**:
1. Map affected services and their boundaries
2. Review `StorageLens.Shared.Contracts` for existing types
3. Design immutable DTOs for new cross-service communication
4. Create or update typed `HttpClient` integrations
5. Add correlation ID propagation and error handling
6. Provide integration tests covering sync points
7. Update architecture documentation and CHANGELOG

**Tools Used**: File search, semantic search, architecture diagram review

---

## Agent: Contract Steward

**Purpose**: Manage API contracts, DTOs, and backward compatibility.

**When Invoked**:
- Ask: "How should I version this API change?"
- Ask: "What contracts do we share with the Web UI?"
- Ask: "Is this API change backward compatible?"

**Behavior**:
1. Review existing contracts in `StorageLens.Shared.Contracts`
2. Check API usage across services via grep/semantic search
3. Assess backward compatibility impact
4. Suggest versioning and migration strategy if breaking
5. Ensure immutability and serialization correctness
6. Update API documentation and CHANGELOG

**Tools Used**: File search, grep, API docs review

---

## Agent: Test & Documentation

**Purpose**: Ensure test coverage and documentation compliance.

**When Invoked**:
- Ask: "Generate tests for this service"
- Ask: "What documentation needs updating for this change?"
- Ask: "Is my test coverage adequate?"

**Behavior**:
1. Analyze code for test coverage gaps
2. Review `docs/` for relevant sections to update
3. Check if CHANGELOG needs entry
4. Suggest test cases (unit, integration, edge cases)
5. Verify documentation guard compliance
6. Link to CI workflows that enforce these rules

**Tools Used**: Test runner, file read/write, grep

---

## Agent: Architecture Reviewer

**Purpose**: Validate changes against microservices principles.

**When Invoked**:
- Ask: "Should this new feature go in Locations or Duplicates?"
- Ask: "Is this design respecting service boundaries?"
- Ask: "How should this cross-service feature be structured?"

**Behavior**:
1. Review microservices architecture docs
2. Identify service ownership and responsibility
3. Check for anti-patterns (cross-DB access, tight coupling)
4. Suggest proper HTTP contract and retry strategies
5. Validate error handling and logging approach
6. Recommend architecture documentation updates

**Tools Used**: Architecture docs, semantic search, diagram tools

---

## Agent: DevOps & Deployment

**Purpose**: Assist with Docker, Bicep, and deployment concerns.

**When Invoked**:
- Ask: "How do I add a new service to docker-compose?"
- Ask: "Update deployment for the new Hashing service"
- Ask: "What Bicep changes are needed for this feature?"

**Behavior**:
1. Review current `docker-compose.yml` and `infra/main.bicep`
2. Check deployment documentation in `docs/operations/`
3. Suggest Docker image, port, and volume configurations
4. Update Bicep for Azure resources and networking
5. Provide local development setup instructions
6. Update deployment and scaling guides

**Tools Used**: File read/write, Bicep schema tools, Docker utilities
